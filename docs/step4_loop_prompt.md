# FarmShare loop prompt (from 2026-11-16)

This one `/loop` prompt runs three campaigns in one FarmShare Claude session:
- (A) the update-bonus campaign (`docs/step4_bonus.md`);
- (B) the no-regulariser failure campaign (`docs/step4_noreg_fail.md`);
- (C) the compensated-correction campaign (`docs/step4_comp.md`). It was added on 2026-11-16 to the 2026-11-14 prompt, which ran (A) and (B).

It replaces the optimal campaign's prompt (`docs/step4_optimal.md`, "Prompt"). That campaign is paused: its running jobs finish on their own.

```
/loop You are running three Step 4 campaigns of this repo (~/reward-hacking-with-observer) on Stanford FarmShare. Read CLAUDE.md (§4f, §6 FarmShare), docs/step4_bonus.md, docs/step4_noreg_fail.md, docs/step4_comp.md and docs/step4_optimal.md before doing anything. The three campaign docs are the source of truth for their campaigns; docs/step4_optimal.md supplies the criteria, decision rules and commands they refer to, as changed by each campaign doc. Follow them exactly.

The campaigns:
(A) CAMPAIGN=bonus: the mentor's update bonus (protocol.update_bonus=1.0: +1 received reward every time the reward function is updated), 12 cells: grid, absent_supervisor, tomato, tomato_large x swap (P2swap), no-regulariser (P1eq1), standard PBRR (base). Log: docs/step4_bonus_log.md.
(B) CAMPAIGN=noreg_fail: no-regulariser PBRR (P1eq1) in the environments where its exact optimum is not the desired behaviour (corrected, then honest): taxi and boat_race, 2 cells. Log: docs/step4_noreg_fail_log.md.
(C) CAMPAIGN=comp: the compensated correction (standard PBRR's fit applied as fines only, never relaxed within an episode, plus a level per step that pays back each correction: g.fine_only=True g.offset=True g.offset_margin=0.0), 6 cells: grid, absent_supervisor, tomato, tomato_large, taxi, boat_race. Log: docs/step4_comp_log.md.
Goal in all three: PPO must reach (almost exactly) its exact optimum, i.e. be within 3% of the best response to the corrections its own play induces (experiments/step4_br.py, the verdict); the self-consistent targets (experiments/step4_targets.py) give the exact end states and are the answer to report. Keep tuning (extend / ppo / explore, rule 6b) until every cell has a config CONVERGED in 3/3 tuning seeds and 3/3 fresh confirmation seeds; never close a cell as a finding.

EVERY scripts/farmshare/step4_optimal.sh command you run starts with CAMPAIGN=bonus, CAMPAIGN=noreg_fail or CAMPAIGN=comp (plus EXCLUDE=<broken nodes> while a node is broken). A command without CAMPAIGN= acts on the paused optimal campaign (results/step4/*/optimal): never run one; no resume, extend, confirm, checks or new runs there. Don't cancel any job you did not submit.

Each iteration:
0. First iterations. If docs/step4_bonus_log.md does not exist yet: git pull --no-rebase --no-edit --ff; run `.venv/bin/python tests/test_step4.py` (all must pass); for campaigns bonus and noreg_fail dry-run, check, then submit `CAMPAIGN=<c> bash scripts/farmshare/step4_optimal.sh targets submit` and `CAMPAIGN=<c> bash scripts/farmshare/step4_optimal.sh wave1 submit` (bonus: 12 target jobs + 20 runs; noreg_fail: 2 target jobs + 6 runs; Taxi's existing seed 0-2 targets are skipped, not overwritten). If docs/step4_comp_log.md does not exist yet: git pull --no-rebase --no-edit --ff; run `.venv/bin/python tests/test_step4.py` (all must pass); dry-run, check, then submit `CAMPAIGN=comp bash scripts/farmshare/step4_optimal.sh targets submit` (6 jobs), `CAMPAIGN=comp bash scripts/farmshare/step4_optimal.sh compare submit` (4 jobs: the swap's and standard PBRR's targets in Taxi and Boat Race) and `CAMPAIGN=comp bash scripts/farmshare/step4_optimal.sh wave1 submit` (18 runs). Create each missing log (append-only: date, what you saw, what you decided, the exact commands, job ids; keep "Flags for the user" and "Exact predictions" current at the top of each) and commit.
1. git pull --no-rebase --no-edit --ff (never --rebase or --autostash); squeue -u $USER; `CAMPAIGN=bonus bash scripts/farmshare/step4_optimal.sh report`, `CAMPAIGN=noreg_fail bash scripts/farmshare/step4_optimal.sh report` and `CAMPAIGN=comp bash scripts/farmshare/step4_optimal.sh report`.
2. For each campaign, apply the decision rules in order: resume (runs stopped by the 48 h time limit), new targets, best-response checks (`CAMPAIGN=<c> ... br_missing submit`), finished runs (confirm / extend / plateau), wave 2, wave 3, exploration (6b), budget (bonus <= 60 jobs, noreg_fail <= 20, comp <= 30, and all your jobs together <= 110 of the 128 allowed). Always dry-run a command (omit "submit") and check it before submitting. Log every decision and command in that campaign's log.
3. As soon as a target is computed, write it at the top of its log under "Exact predictions": bonus, with the no-bonus comparison for swap and no-reg (same seed, results/step4/<env>/targets/<variant>/) and whether base hides; noreg_fail, against honest (Taxi 125, Boat Race 50) and whether the behaviour after the correction is honest, the original bug, or a new exploit; comp, as its doc's rule 2 says (true by round against honest, each correction's level, the same seed's swap and standard-PBRR targets, and whether the behaviour after the correction is honest, the original bug, or a new exploit). These are the answers; never adjust environments, criteria, the bonus, the mechanism or targets to get a hoped-for result.
4. Commit with `bash scripts/farmshare/step4_commit.sh "<short message>"` (never git add running seeds' checkpoint files by hand; never overwrite or delete a run).
5. If something is broken (a job crashes, a script errors, a fixed point does not converge, a check fails), log it with the error text, fix only what is clearly a bug (commit the fix with a test), and otherwise flag it at the top of the log for the user instead of improvising. If a job fails or is killed by a cluster incident (not the 48 h limit), flag it for the user and don't resubmit it without the user.
Pace: wake every ~45 min while jobs run (~2 h when only long runs remain). Stop when every cell of all three campaigns is DONE or the user says stop, after writing each campaign's final summary at the top of its log.
```
